Virtual Kubernetes Engineer — where it stands

One engineer. Four ways to run it. A loop that compounds.

VKE is a self-improving SRE platform: ~35 role-gated tiles across Observe · Converse · Act · Learn · Oversight · Admin, all views over one append-only, hash-chained event log. It watches a cluster, proposes fenced fixes behind human approval, and — the differentiator — turns its own incident history into training data. The Training Studio takes anyone from "pick a model" to "chat with the model you just trained" in five guided steps, with a cost gate before anything runs and a real loss curve while it does.

All of that now ships four ways from one codebase, on one version channel (Settings → Updates), with in-app support tickets, and a release pipeline whose additive gate refuses any change that would break a shape.

Architecture

How VKE works — one log, three faculties, one alias.

Reinforcement learning, optimized

Observe → Learn → Iterate: the loop is the product.

VKE runs a reinforcement-learning-shaped flywheel with a human hand on the reward signal. The environment is your cluster. The actions are fenced remediations. The reward is a human approval followed by a verified outcome. And the policy genuinely updates — first as knowledge, then as model weights, then as earned autonomy. Optimized, here, means the expensive parts are gated and the loop never trains on unverified experience.

1

Observe — dense, cheap, continuous

state → the event log

Live cluster state, rule-based alerts, and the predictive engine stream into the hash-chained event log. Every incident gets a normalized signature (the state abstraction that makes experience reusable), and the agent loop sweeps hourly so nothing depends on a human watching a dashboard.

2

Learn — reward-filtered experience becomes weights

approved outcome → dataset → LoRA → the alias

Only trails that ended in an approved, successful fix become incident→fix training rows — the reward filter — and a consensus council can vet each remediation row before export. The Training Studio turns that corpus into a LoRA (seconds on MLX, minutes on CPU), replay-verify checks the trained model reproduces the fixes humans approved, and Promote hot-swaps the k8s-sre alias onto the new weights. Cloud assistance, where used, is transitional by design: its fixes train the local model until the fix-class no longer needs the cloud.

3

Iterate — more experience, better policy, earned autonomy

append → v2 → graduation

Append fresh incidents (or your own data) and train v2 on top of v1 — the run history overlays the real loss curves so improvement is visible, not claimed. In parallel, the policy itself graduates: a fix-class moves shadow → proving → learned → autonomous only when it has repeated successes, a high success rate, local-model reproduction, and an explicit human enable — with a circuit breaker and automatic demotion when reality disagrees. That's the exploration/ exploitation dial, held by you.

Why this converges: every day the corpus grows, the local model reproduces more of the cluster's own fixes, and more fix-classes run without a page. The same loop that fixes your cluster is the loop that trains your engineer — a monitoring tool tells you something broke; VKE gets better at fixing it.
