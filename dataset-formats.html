Telemetry logs → training pairs: the six upload shapes

The Studio's Add data step accepts the same incident, one row per line, in any of the shapes below — JSONL pair-styles or a plain 2-column CSV. Every row is normalized to one canonical chat-messages format and PII-redacted before it is stored, so the trainer (MLX on a Mac, peft on the appliance, the sidecar in-cluster) always sees identical input regardless of how you exported your telemetry.

Your telemetry exportkubectl · Loki · PagerDuty · runbooks · CSV → Upload / pasteshape auto-detected per row → Normalize→ chat-messages JSONL → PII redactemails · hosts · tokens → Trainfamily template applied at serve
The running example — one real incident class from the bundled sre-pods-100 dataset (the same corpus the ft.dkube.app demo trained on): the payments-api CrashLoopBackOff, with its kubectl evidence as the input half and the verified fix as the output half. Each table below shows the SAME incident, just wearing a different pair shape.

1 · messages — the canonical chat shape canonical · passed through as-is

What every other shape is converted INTO, and what the bundled datasets (sre-pods-100, sre-pods-append-50, k8s-troubleshooting) already use. Carries an explicit system turn — for Gemma bases the system turn is folded into the first user turn automatically (Gemma templates take no system role).

2 · prompt / completion classic OpenAI-SFT style

The oldest fine-tuning export shape — most log-labeling pipelines and the ft.dkube.app generator can emit it directly. The prompt half carries the raw telemetry; the completion is the resolution note.

3 · instruction / output Alpaca / runbook style

Natural when the source is a runbook or playbook rather than raw logs — the instruction reads like a task, the output like the procedure. Good for teaching the model your house remediation style.

The shape most log-summarization exports land in: raw machine telemetry in, a human-grade reading out. Ideal for teaching “read this wall of events and say what matters.”

For spreadsheet people: first column = the question/telemetry, second column = the answer. A header row (prompt, question, input, instruction, user, q) is auto-detected and skipped; tabs auto-detected from the first line.

What happens to every row, whichever shape it arrived in

StepWhat it doesWhy it matters
NormalizeEvery shape above → the canonical {"messages":[…]} row; a default SRE system turn is added where the shape has none.The three trainers (MLX · peft-CPU · in-cluster sidecar) share one input contract — no per-format code anywhere downstream.
PII redactEmails, IPs, API keys and JWTs are scrubbed from every turn before the file is written. Cluster hostnames and service names are deliberately kept — in SRE telemetry they are the training signal.Nothing sensitive can leak into an export or a cloud cmd/ call later — redaction happens at the door, not at egress.
Skip & countUnparseable lines are skipped, never fatal; the response reports added / rows / skipped.A half-messy log export still yields a usable dataset instead of an error wall.
Appendappend=true grows an existing set (the sre-pods-append-50 story).Powers “Retrain +data”: v2 trains from the fused v1 on the grown set, and the loss overlay shows the head start.
Family templateAt serve time the trained model is imported with its base family's chat template (ChatML · Llama 3 · Gemma · Mistral); Gemma bases get the system turn folded.The answers come back through the same conversational grammar the base was pre-trained on — no degraded output from a mismatched template.
